## 🔍 Committed Predictions & Zero-GPU Verification

To guarantee **100% scientific transparency and reproducibility without requiring access to an NVIDIA H100 GPU cluster**, every evaluated method logs a structured prediction JSON file for each of the 8 projects (e.g., `ZERO_SHOT_QWEN_HARD/AAH_predictions.json`).

Each prediction record contains the complete verification trace:
```json
{
  "source_id": "AAH-101",
  "target_id": "AAH-504",
  "label": 1,
  "prediction": 1,
  "raw_response": "{\"is_linked\": true}",
  "latency_ms": 984.2,
  "input_tokens": 372,
  "generated_tokens": 7,
  "truncated": false
}
```

By retaining all 205 prediction logs across all methods (`~150 MB total uncompressed`), any researcher or examiner can immediately verify every cell in the thesis results tables, recompute clean vs. conservative scoring penalties, or run custom statistical analyses on standard consumer hardware.

## 📊 Summary of Master Statistical JSONs

### 1. `significance_tests_clean_f2.json`
Generated by `SCRIPT/10_significance_tests.py`, this file evaluates whether performance differences between methods across the 8 industrial projects ($N=8$) are statistically robust:
* **`Sign Test (p-value)`:** Tests consistency of project wins across the 8 benchmarks.
* **`Paired Wilcoxon Signed-Rank Test (p-value)`:** Accounts for both direction and magnitude of score differences.
* **`Bootstrap 95% Confidence Interval`:** 10,000-iteration Monte Carlo resampling over the project F2 differences (`delta = A - B`).

**Key Verification:** When comparing `Combined LoRA+RAG` against `RAG-B`, the Wilcoxon $p$-value (`0.3828`) and Bootstrap CI (`[-0.0154, +0.0298]`) confirm that the difference is **not statistically significant ($p > 0.05$)**. This proves that once an open-weight LLM is provided with high-quality dynamic retrieval demonstrations (`RAG`), adding internal LoRA adapter weights does not yield a statistically reliable advantage across diverse projects.

### 2. `stratified_by_link_type_v3.json`
Generated by `SCRIPT/9.stratified_eval_by_link_type.py`, this analysis breaks down classification accuracy across the two dominant structural relationships found in real-world Jira repositories:
* **`Standard -> Child` (Subtask Decomposition):** Finer-grained operational breakdown (e.g., Task to Subtask). All models achieve higher recall (`~88-92%`) on these pairs due to direct structural and lexical alignment.
* **`Parent -> Standard` (Epic / Feature Refinement):** Broad architectural alignment (e.g., Epic to Task). These links remain consistently harder across all evaluated architectures (`~71-78%` recall), isolating abstraction bridging as the primary remaining challenge in LLM-based requirements engineering.
